# 로컬 음식 사진 CV·VLM 보완 적용

## 활성화와 실행

- 적용 저장소: `local-develop`, 로컬 API `http://127.0.0.1:8000`.
- 로컬 설정의 `OPENAI_VLM_FALLBACK_ENABLED=true`, 모델 `gpt-4o-mini`.
- `OPENAI_API_KEY_FILE`은 로컬 키 파일 경로만 저장한다. 실행기가 키를 읽어 서버 프로세스의 `OPENAI_API_KEY`에 주입한다. 키 값은 저장소·로그·프런트엔드·테스트 결과에 기록하지 않는다.
- 실행 시 이미 `OPENAI_API_KEY`가 설정돼 있으면 파일보다 우선한다. 활성화 상태에서 키가 없거나 파일에 여러 키가 있으면 실행을 중단한다.
- 키 파일 경로·설정 변경 뒤 `scripts/stop-local-mobile.ps1`, `scripts/start-local-mobile.ps1`로 로컬 서버를 재시작한다. 설정 파일과 원본 사진은 Git에서 제외된다.
- 2026-10-09 공개 시연 사진의 실제 OpenAI Responses 요청 성공: `local_kfood_openai_vlm`, `needs_confirmation`. 서버 `/api/v1/ready`의 VLM enabled/ready 모두 true. Ready는 구성 확인이며 실제 연결 성공은 별도 요청 결과로 확인했다.

## 인증 흐름

1. 채소 사진 화면에서 김치, 채소를 덮는 진한 양념/소스, 흰 음식과 흰 식기/배경을 각각 `있음/없음/잘 모르겠음`으로 입력한다. 기본값은 `잘 모르겠음`이다.
2. 서버는 파일 형식·크기·화소를 검사하고 JPEG로 변환해 EXIF와 위치정보를 제거한다.
3. 기존 EfficientNet-B0 음식 분류기와 TFLite 픽셀 분할기를 실행한다. 음식 면적 50%, 음식 안 채소 면적 30% 기준을 유지한다.
4. CV가 불확실하거나 기준 근처이거나 사용자 체크 중 하나라도 `yes/unsure`이면 VLM을 호출한다. 모두 `no`여도 CV가 불확실하면 보완한다. 예전 클라이언트가 필드를 보내지 않으면 기존 CV 조건으로 보완한다.
5. VLM은 식사 관련성, 채소 확인 가능성, 사진 품질, 음식/배경과 채소/다른 음식의 경계, 화면 캡처 여부만 검토한다. 사용자 체크는 정답으로 취급하지 않는다. VLM은 면적·중량·영양소·실제 섭취·혈당이나 치료 효과를 추정하지 않는다.
6. **CV의 면적 기준과 신뢰도가 모두 충족되고 VLM 검토도 명확한 경우에만** `needs_confirmation`으로 진행한다. 사용자가 같은 사진·같은 체크 답변으로 최종 확인해야 `accepted`와 완료 기록이 저장된다.
7. CV 면적이 미달하거나 분할이 불확실한데 VLM은 채소를 확인했다면 `needs_review`로 보류한다. VLM이 채소가 보인다고 면적 기준을 대신 충족시키지 않는다. 경계·품질 불명확, 결과 충돌, API 오류도 보류한다. 식사와 무관하거나 화면 캡처로 판정되면 거절한다.

최종 확인의 사진 해시는 체크 답변도 포함한다. 답변을 바꾸면 새 검토 초안이 필요하다. 동일 날짜의 이미 완료된 기록은 중복 저장하거나 보상을 추가 지급하지 않는다. 활동 사진은 음식 체크와 VLM 흐름을 사용하지 않는다.

## 보완 범위와 한계

VLM은 김치·양념 채소의 의미 확인과 흰 음식/흰 식기의 경계 문제를 감지하는 보완 장치다. **분할 마스크를 수정하거나 새 면적을 계산하는 모델은 아니다.** 기존 CV가 김치를 불확실한 음식으로 표시한 경우 VLM만으로 그 불확실성을 제거하지 않는다. 사진을 다시 찍어도 지속되는 면적 오류는 별도의 분할 모델 개선과 정답 마스크 검증이 필요하다.

사용자 체크를 끄거나 `없음`으로 답했다고 기준을 낮추지 않으며, 체크 내용 자체로 통과하지 않는다. 외부 검토에 보내는 것은 정제한 사진과 세 개의 체크 답변이다. 이름·계정·건강 측정값·원본 파일명·EXIF는 보내지 않는다. OpenAI 요청은 `store=false`와 엄격한 JSON Schema를 사용한다.

## 검증

- CV 판정, 인증 API, 키 파일 로딩 회귀 테스트: 114개 통과.
- 사진 프런트엔드 테스트: 14개 통과. 모바일 패키징·통신 테스트: 15개 통과.
- 경계값 미달·잘못된 수치·CV 불확실성·VLM 불명확/실패는 자동 완료되지 않음을 확인했다.
- 같은 사진에서 체크 답변을 바꾸면 이전 확인 초안을 사용할 수 없으며, 정상 최종 확인 후에도 완료 기록은 한 개임을 확인했다.
- 390·720·1280px 오류 안내 화면 레이아웃 검증 통과. 취약 조건 입력·보류 화면 검증은 `scripts/mobile/check-vlm-photo-flow.mjs`로 실행한다.

## 공개 사진 비교 실험

수집기: `scripts/collect-food-photo-benchmark.py`. 평가기: `src/ml/evaluation/food_photo_benchmark.py`.

- 공개 [한식 이미지 데이터](https://huggingface.co/datasets/Jiho0o0/kfood_image_englabel)와 [MM-Food-100K](https://huggingface.co/datasets/Humanbased-AI/MM-Food-100K)에서 김치와 조리된 밥을 각 100장 선택한다.
- 난수 시드 `20261009`, 출처 행·데이터셋 revision·이미지 SHA256·해상도를 저장한다. 최소 변 128px, 정제 JPEG 최대 1600px. 원본 의료 데이터와 사용자 사진을 사용하지 않는다.
- 픽셀 중복 및 dHash 거리 3 이하의 유사 사진을 제외한다. 육안 점검에서 생쌀로 보인 밥 라벨 표본도 제외한다. 수집 데이터·사진·결과는 `outputs/food_photo_benchmark_20261009/`에만 저장한다.
- 실제 CV와 VLM 요청을 실행하며, CV 숫자는 고정한 채 사용자 체크를 포함한 보완 검토 결과를 비교한다. 동시 OpenAI 요청은 기본 3개다. 실제 사용자 챌린지 DB에는 기록하지 않는다.
- 음식 이름 라벨은 정확한 면적 마스크나 인증 정답이 아니다. 이 실험의 통과/보류 비율을 모델 정확도라고 해석하지 않는다. 기존 CV 학습 데이터와의 중복 여부는 확인되지 않았다. 기준이나 모델을 이 표본으로 튜닝하지 않는다.
