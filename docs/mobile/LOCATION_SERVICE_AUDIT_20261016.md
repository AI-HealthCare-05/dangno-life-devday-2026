# 위치 서비스 점검 — 2026-10-16

## 현재 흐름

- 결과·건강도구의 주변 의료기관 검색은 화면의 버튼을 누를 때만 웹 위치 API를 호출하고 5km 범위를 서버에 요청한다. 긴급 안내의 주변 응급의료기관은 위치 확인 후 10km 범위를 요청한다. 위치를 구할 수 없거나 거부되면 주소 입력 경로를 보여 준다.
- 첫 위치 조회는 배터리 부담이 적은 정확도·5분 이내 캐시를 사용한다. 위치 확인 실패/시간 초과 때만 높은 정확도로 한 번 재시도한다. 권한 거부는 재시도하지 않는다.
- 의료기관 API는 로그인 필요, 위도·경도 범위와 검색 반경을 검증한다. 카카오 장소 검색·국립중앙의료원 응급기관 API를 연결하는 서버 코드가 있다. 지도는 카카오 JavaScript 키가 있을 때 별도로 로드한다. 지도 로드에 실패해도 의료기관 목록은 보존한다.
- 이 로컬 서버는 `MEDICAL_FACILITY_SEARCH_PROVIDER=development`이고 카카오 검색·지도 키와 NEMC 키가 설정되지 않았다. 개발용 의료기관 결과는 실제 기관으로 표시하지 않으며, 실제 응급기관 조회도 연결되지 않는다. API는 비로그인 요청에 401을 반환한다. 실제 서비스를 쓰려면 서버 환경변수에 공급자·키를 설정해야 한다. 키 값을 앱에 포함하거나 Git에 넣지 않는다.

## 확인된 문제와 수정

- 이전 Android APK의 병합 manifest에는 인터넷 권한만 있었고 `ACCESS_COARSE_LOCATION`·`ACCESS_FINE_LOCATION`이 없었다. Capacitor WebView의 위치 권한 요청 코드는 두 권한을 확인하므로, 두 권한을 Android manifest에 선언했다. 위치는 버튼 클릭 시에만 요청한다.
- iOS Info.plist에 `NSLocationWhenInUseUsageDescription` 안내가 없어 추가했다. Windows 환경이므로 iOS 실기기 권한·위치 취득은 검증하지 못했다.
- 응급기관 검색에 쓰는 확인된 위치는 1분만 재사용하고, 위치 재확인 실패나 로그아웃 시 삭제한다. 오래된 좌표를 다음 검색에 보내지 않는다.

## 검증

- 위치 재시도, 권한 거부, 오래된 좌표 제거를 메인·인트로 화면 테스트로 확인했다. 의료기관·응급기관 공급자 및 API 연결 관련 Python 테스트도 통과했다.
- Android 빌드 후 APK의 병합 권한, 패키지 구분 및 로컬 API 주소를 검사한다. 실기기 GPS와 외부 의료기관 공급자는 현재 설정상 확인되지 않으므로 연결 성공으로 표시하지 않는다.
- Python 의료기관·화면 연결 테스트 24개, JavaScript 위치·권한 거부 테스트 12개가 통과했다. Python 테스트 중 Windows 콘솔 인코딩으로 발생한 백그라운드 출력 경고 1건은 테스트 실패가 아니다.
- 로컬 APK `outputs/location-service-20261016/gandang-local-location.apk`의 패키지는 `life.dangno.app`이며, 병합 manifest에 인터넷·대략적 위치·정확한 위치 권한이 모두 포함된다. SHA-256은 `66948cc46b42b983b21943e8505ad50dc22c5c49d77974b87b6607b6a87f37dc`다.
- BlueStacks 로컬 앱에 데이터 유지 업데이트 후 실행했다. 설치된 APK 해시가 빌드본과 일치하고 위치 권한 선언을 확인했다. 배포 앱의 갱신 시각은 그대로다. 실제 위치 기반 기관 검색은 공급자 키가 없어 검증하지 못했다.
