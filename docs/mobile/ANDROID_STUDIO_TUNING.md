# Android Studio에서 당근의 숲 성능·메모리 점검

2026-10-13. 대상은 BlueStacks와 S25의 `life.dangno.app.deployment`이며 서버는 `https://www.dang-no.life`이다.

## 개발 환경

- Android Studio Rabbit 1 / 2026.2.1.8 공식 Windows ZIP의 SHA-256을 확인하고 상위 작업 폴더의 `outputs/tools/android-studio`에 준비했다.
- IDE는 번들 JBR 25를 사용한다. 프로젝트 Gradle 8.14.3은 Java 21을 사용하도록 별도로 구성했다. Gradle/AGP 버전을 변경하지 않았다.
- Android SDK Platform 36과 Build Tools 36.0.0을 준비했다. SDK 경로는 `local-develop/outputs/mobile/toolchain/sdk`이다.
- IDE에 연 프로젝트는 이 저장소의 `src/frontend/native/android`이다. CLI의 `-PmobileDeployment=true help` 및 `assembleDebug`가 통과했다.
- SDK 경로, 로컬 Gradle/JDK 설정과 IDE 캐시는 개발 환경에만 저장하며 Git에 포함하지 않는다.

## 적용한 변경

1. 모바일 캔버스는 실제 디스플레이 배율을 사용한다. 1~2배 범위와 4096픽셀 최대 변 제한을 유지한다. 웹의 기존 2배 배율은 유지한다. 카메라 배율 보정으로 월드 좌표·이동 속도·터치 위치가 달라지지 않는다.
2. 3072×2048 당근밭 주간 표시 레이어는 초기 숲에서 생성하지 않고 첫 당근밭 진입에서 생성한다. 이후 진입에서는 같은 레이어를 재사용한다. 당근 30개, 주간 안내, 4배 원본 레이어 해상도는 유지한다.

## 설치·검증 범위

설치된 기존 APK는 작업 소스와 자산 구성이 달랐다. 검증용 업데이트는 기존 APK의 네이티브 코드와 모든 다른 자산을 유지하고 `assets/public/static/forest-phaser.js`에 위 두 변경만 적용했다. 다른 파일이 변경되지 않았음을 ZIP 내용 비교로 확인했고, 기존 디버그 서명과 일치하는 것을 확인한 뒤 `adb install -r`로 업데이트했다. 이 APK를 프로젝트 전체 Gradle 빌드 산출물과 혼동하지 않는다. 전체 Gradle 빌드는 별도로 성공했다.

상위 작업 폴더의 검증 APK: `outputs/android-studio-tuning-20261013/gandang-deployment-memory.apk`. 비교용 기존 APK도 같은 폴더에 보관했다. 운영 서버 업로드와 커밋·푸시는 하지 않았다.

### 확인한 값

| 첫 숲 진입 항목 | 이전 | 수정 후 |
| --- | ---: | ---: |
| 화면 CSS 크기 | 720×1256 | 720×1256 |
| 캔버스 크기 | 1440×2512 | 1080×1884 |
| 단일 캔버스 RGBA 버퍼 계산값 | 14,469,120 B | 8,138,880 B |
| Phaser 이미지 소스 RGBA 추정 합계 | 184,804,424 B | 159,638,600 B |
| Phaser 텍스처 개수 | 86 | 85 |
| 앱 본체 PSS 스냅샷 | 262,925 KiB | 239,022 KiB |
| WebView 렌더러 후보 PSS 스냅샷 | 379,357 KiB | 333,545 KiB |

이미지 버퍼 계산상 약 30MiB를 최초 숲 화면에서 줄였다. 텍스처 추정치는 `width × height × 4`이며 실제 앱 메모리와 같지 않다. PSS는 각각 한 번의 스냅샷이며 가비지 수집, 코드 매핑, 공유 프로세스, 캐시 준비 상태의 영향을 받는다. 렌더러는 다른 Chrome 화면과 혼동하지 않도록 앱 재실행에 따라 새로 생긴 격리 프로세스를 추적했다. 앱 하나의 Java 힙만으로 WebView 전체 사용량을 판단하지 않는다.

이전 측정 프레임 간격 중앙값은 25ms, 수정 후 한 차례 측정은 16.7ms였으나 PC의 IDE 인덱싱/빌드 부하와 측정 시점이 달랐다. 배율만 일시적으로 바꾼 비교에서는 중앙값이 동일했다. 따라서 일정한 FPS 개선을 입증한 결과로 쓰지 않는다. 실제 GPU 표시 완료 시간도 측정하지 않았다.

### 기능 검증

- 카메라·터치 역변환·당근밭·포인터 조작·기존 먹이주기·미리보기 관련 Node 테스트 58개 통과.
- 설치된 APK에서 작은 캔버스, 초기 당근밭 레이어 미생성, 당근밭 첫 진입 표시와 재진입 재사용을 확인했다.
- 숲 저장 문자열의 SHA-256은 업데이트 설치 전후와 장면 검증 후 동일했다. 저장 원문·토큰·계정 정보는 기록하지 않았다.
- 당근밭에 들어간 이후 레이어 메모리는 유지된다. 이 변경은 첫 숲 진입 비용을 줄이며 당근밭 방문 후의 모든 메모리를 절감하는 기능은 아니다.

## Profiler 다음 단계

사용자가 Windows 방화벽 확인창을 닫은 뒤 Profiler에서 실행 중인 `life.dangno.app.deployment`를 선택하고 View Live Telemetry까지 선택했다. 그러나 현재 BlueStacks는 Android 9 / API 28이며 시작 시점 옵션이 비활성화되어 GUI 측정을 시작하지 못했다. 최신 Android Studio의 공식 기본 프로파일링 요건은 API 29 이상이다. S25 또는 Android 11 이상 BlueStacks에서 이어서 검증해야 한다. 기본 로컬 앱 `life.dangno.app`와 혼동하지 않는다. 이번 메모리 수치는 ADB/CDP 측정이며 Profiler 녹화 결과가 아니다.

가능한 녹화 작업은 OS와 디버그 설정에 따라 다르므로 해당 장치에서 제공되지 않는 native allocation 작업을 완료한 것으로 취급하지 않는다. 로그나 힙 덤프에 사용자 데이터가 포함될 수 있으므로 공유하지 않고, 합계·프레임·버퍼 수치 중심으로 기록한다.

공식 참고: [Android Studio Profiler](https://developer.android.com/studio/profile), [WebView 메모리 관리·진단](https://developer.android.com/develop/ui/views/layout/webapps/manage-webview-memory).

## S25 닉네임·초기 이미지·배치 버튼 수정

### 확인한 원인

- 캐릭터 위 이름은 계정으로 동기화한 게임 상태보다 렌더러의 이름을 우선했다. 렌더러 생성 전에 이름 변경 이벤트가 지나가면, 상단은 계정 이름인데 캐릭터 위에는 저장된 게스트 별칭이 남을 수 있었다. 일시적인 조회 오류도 `null`로 처리되어 게스트 이름으로 바뀌었다.
- 회전·배치 확정과 취소 버튼은 전체 화면 전환 후 숨기는 옛 `tool-rail` 안에 남아 있었다. S25 배치 모드에서 버튼의 `hidden`은 해제됐지만 실제 너비·높이가 0이었다.
- 집 안 전축의 `home-record-player-cottage-v1.png`는 로컬 소스에 있으나 현재 작업 소스와 S25 APK에는 없었다. Phaser가 누락 텍스처를 만들었으며 생성 시 무조건 표시한 뒤 장면 동기화 시 숨겨 최초 진입·초기화 직후 검정·초록 사각형이 잠깐 보였다.

### 변경과 검증

- 입장 인증에서 확인한 표시 이름만 메모리로 전달하여 게임 상태와 렌더러의 최초 이름을 맞춘다. 이름표는 게임 상태의 이름, 위치는 카메라 좌표를 사용한다. 서버 오류·네트워크 단절·시간 초과 때 기존 이름을 유지하고, 확인된 인증 실패 때만 이름을 해제한다. 계정 이름을 게스트 저장 데이터에 기록하지 않는다.
- 기존 버튼을 복제하지 않고 게임 프레임 안으로 옮긴다. 하단 탭 위에서 회전·배치 확정·취소를 표시하며 위치 선택 전 확정은 비활성이다. 배치 중 이동 버튼을 가려 겹침을 막고 취소하면 복구한다.
- 기존 전축 이미지를 소스·모바일 자산에 포함한다. 집 안에서만 표시하고 이미지 로딩 실패 시 누락 텍스처 오브젝트를 만들지 않는다.
- 관련 Node 테스트 74개와 실제 브라우저 배치 UI 테스트 1개가 통과했다. 320×640, 360×740, 411×808, 808×411, 1440×900에서 버튼 표시·화면 내 위치·원래 클릭 동작·취소 후 숨김을 확인했다. 계정 초기 이름, 오래된 렌더러 이름, 503·네트워크·시간 초과·로그아웃도 검증했다.
- Android `assembleDebug` 성공. S25에는 설치된 기존 APK의 네이티브 코드와 다른 자산을 유지하고 수정한 화면 파일 6개와 전축 이미지 1개만 반영했다. 기존 디버그 서명을 확인하여 업데이트 설치했다. 로컬 앱 패키지는 건드리지 않았다.
- S25 설치 후 로그인 유지, 상단·이름표·렌더러의 계정 이름 일치와 누락 텍스처 0개를 확인했다. 창고에서 위치 선택 후 회전·확정·취소 버튼이 활성화되고 화면 안에서 터치 가능했다. 확정 저장은 수행하지 않고 취소했으며 해당 검증 전후 숲 저장 해시가 동일했다. 일반 플레이 중 이동 등으로 생긴 다른 시점의 저장 변화와 혼동하지 않는다.

상위 작업 폴더의 S25 검증 APK: `outputs/android-studio-tuning-20261013/s25/gandang-deployment-forest-fixes.apk`. 배포 서버에 업로드하지 않았다. 초기화 후 최초 `world` 화면에서도 로그인 유지, 세 곳의 이름 일치, 누락 텍스처 0개, 전축 숨김, 배치 툴바 기본 숨김과 당근밭 레이어 미생성을 재확인했다.

## S25 Profiler·메모리 확인

Android 16 / API 36 S25의 배포 앱에 `View Live Telemetry`를 연결하여 CPU·메모리를 수집했다. 기본 로컬 앱과 다른 앱의 프로세스는 측정하지 않았다. 초기에는 앱이 배경에 있었고 이후 사용자가 숲 화면을 전면에 유지했으므로 전체 기록 시간을 숲 플레이 시간으로 취급하지 않는다.

- 화면 크기 411×808, DPR 2.625로 캔버스는 이전과 같은 822×1618이다. 모바일 배율 제한 2배가 적용되어 S25에서 해상도를 낮추지 않았다.
- 최초 숲의 텍스처 추정 RGBA는 184,450,632→159,656,520바이트였다. 당근밭 24MiB 레이어를 지연 생성한 절감량과 추가 전축 이미지가 함께 반영된 값이다. 3초 rAF 간격 중앙값 8.3ms, p95 8.4ms, 50ms 초과 0회였으며 이전 중앙값·p95도 동일했다. 화면 표시 완료 시간을 뜻하지 않는다.
- Profiler의 한 시점에서 앱 CPU 9%, 표시 메모리 420.2MB(그래픽 265.3MB, Java 14.2MB, Native 42.3MB)를 확인했다. 다른 시점에는 434.6MB·CPU 10%였다. 이는 짧은 실행 구간의 관찰값이며 평균, 최대치, 전체 WebView 메모리가 아니다.
- Profiler 연결 상태의 ADB 앱 PSS는 554,011KiB로, 이전 연결 전 스냅샷 538,254KiB보다 낮지 않았다. 그래픽 항목은 313,652→248,036KiB였으나 측정 시점·Profiler 부하·GC가 달라 앱 전체 메모리 감소를 입증한 수치로 사용하지 않는다. 확인된 개선은 최초 당근밭 텍스처 할당 지연이다.

힙 덤프·사용자 데이터·원문 로그를 공유하거나 저장소에 추가하지 않았으며 실제 녹화와 검증 정보는 로컬 IDE/상위 `outputs`에만 둔다.
