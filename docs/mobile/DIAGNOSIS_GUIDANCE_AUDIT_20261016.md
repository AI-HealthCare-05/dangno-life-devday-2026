# 당뇨병 진단 안내창 기능 점검

2026-10-16. 대상은 로컬 서비스 메인 화면의 ‘이미 당뇨병을 진단받은 사용자는 예측 대상이 아닙니다’ 안내창이다. 실제 이용자 진단 기록·계정·위치는 변경하거나 전송하지 않는다.

## 확인한 문제와 수정

- ‘가까운 의료기관 찾기’, ‘전화 문의 가능한 기관 보기’가 정의되지 않은 `openEligibilityMedicalFacilities`를 호출하여 JavaScript 오류로 멈췄다. 기존 의료기관 검색 UI를 별도 대화상자에서 재사용하도록 연결했다. 진단 상태에서 분석 결과 단계로 이동하지 않는다.
- 390px 화면에서 안내창 내부 너비 346px에 버튼 너비가 760px으로 계산되어 오른쪽으로 잘렸다. 중첩 grid의 최소 너비와 고정 너비를 해제하여 화면 안에서 줄바꿈하도록 수정했다.
- 기존 ‘닫기’는 버튼 클릭·Escape로 동작하지만 Android 뒤로가기의 닫기 탐색 조건에 맞지 않았다. 접근성 닫기 라벨을 추가하여 화면을 이탈하기 전에 안내창부터 닫는다. 인트로의 같은 이용확인 안내에도 닫기 라벨을 적용했다.
- 진단 내역에서 이동하는 건강정보 관리의 의료기관 버튼도 분석 결과 단계로 우회하지 않고 같은 독립 검색창을 열도록 수정했다. 진단 날짜 분석 차단을 해제하지 않는다.
- 두 의료기관 버튼은 같은 검색 화면을 열고 전화번호 유무만 필터링해 목적이 겹쳤다. ‘가까운 의료기관 찾기’ 하나로 통합하고 별도 전화 전용 모드·필터를 제거했다. 검색 결과의 전화 링크로 문의하며, 전화번호가 없는 기관도 숨기지 않는다.

## 버튼별 동작

| 버튼 | 확인한 최종 동작 |
| --- | --- |
| 진단 기록 내역 보기 | 홈의 건강정보 관리·진단 내역으로 이동한다. 진단·건강정보·분석을 새로 저장하지 않는다. |
| 가까운 의료기관 찾기 | 의료기관 전용 대화상자에서 현재 위치 또는 주소로 검색한다. 결과에서 전화·지도 링크를 제공하고 번호가 없으면 ‘전화번호 없음’을 표시한다. 전화 상담 제공 여부는 직접 확인해야 함을 안내한다. 화면을 여는 것만으로 위치를 요청하거나 전화를 걸지 않는다. |
| 진단 안내로 돌아가기 / 검색 화면 뒤로가기 | 검색 UI를 원래 위치로 복원한 뒤 진단 안내창으로 돌아온다. 중복 ID·중복 검색 UI를 남기지 않는다. |
| 닫기 / Escape / Android 뒤로가기 | 안내창을 닫고 이용확인 화면에 머문다. 진단 기록과 해당 날짜 분석 차단은 유지한다. |

## 검증과 한계

- `scripts/mobile/check-diagnosis-guidance.mjs`: 320·390·720·1024px × 기본/큰 글자 8개 배치와 통합 검색 1개 흐름, 총 9개 시나리오를 실제 Chrome에서 검증한다. 중복 버튼 제거, 가로 이탈, 키보드 포커스 순환, 닫기·Escape·Android 뒤로가기, 내역 이동, 위치 거부 후 주소 검색, 전화 링크·번호 없는 기관 유지, 공급자 실패, 개발용 예시 숨김, 검색창 재진입을 확인한다.
- 테스트 API·좌표만 사용한다. 결과 화면은 검증용 기관이며 실제 의료기관이 아니다. 전화 링크의 존재만 검사하고 실제 발신하지 않는다.
- Python 의료기관·화면 연동·진단 내역 테스트 37개, Node 진단·위치·뒤로가기 테스트 30개가 통과했다. Python 하위 프로세스의 Windows 콘솔 인코딩 경고는 별도로 확인한다.
- 화면과 결과 JSON은 Git 제외 경로 `outputs/mobile/diagnosis-guidance/`에 보관한다. 수정 전 오류 재현은 상위 작업 폴더 `outputs/diagnosis-guidance-audit-20261016/`에 보관한다.
- 현재 로컬 서버의 실제 공급자·키 설정은 별도 확인한다. 개발용 공급자 응답은 실제 기관·전화·지도 목록으로 표시하지 않는다. 공급자 키 연결 및 실기기 GPS·실제 의료기관 조회 성공을 합성 검증 결과로 주장하지 않는다.
- `.env.local-mobile`에는 카카오 검색·지도 키가 설정되어 있고 공급자는 `kakao`다. 키 원문은 출력하거나 문서에 남기지 않았다. 같은 로컬 설정을 읽은 서비스로 고정된 공개 서울시청 좌표 반경 5km를 실제 카카오에 조회해 의료기관 15곳, 전화번호 15개, 지도 링크 15개를 확인했다. 실제 사용자 위치와 계정은 사용하지 않았고 전화 발신도 하지 않았다. 결과 합계는 상위 `outputs/diagnosis-guidance-audit-20261016/provider-check.json`에 보관한다. 기기 GPS 취득 및 지도 JavaScript SDK 렌더링은 이 공급자 검증에 포함하지 않는다.

## 로컬 설치

- `-PmobileDeployment=false`로 빌드했다. 로컬 패키지는 `life.dangno.app`, 서버 주소는 `http://127.0.0.1:8000`이다.
- 상위 `outputs/diagnosis-guidance-audit-20261016/gandang-local-guidance.apk`에 버튼 통합 검증본을 보관한다. 크기 420,214,421 bytes, SHA-256 `8311a05443142f86e5fb53e018ff3b20b18970f5732fc203bb5a4bf24598ecdd`.
- 버튼 통합 후 Chrome 9개 시나리오와 Node 30개 테스트를 다시 통과했다. 블루스택에 기존 데이터 유지 업데이트 후 실행했다. 설치 APK의 해시가 일치하며 갱신 시각은 `2026-10-16 15:44:47`이다. 8000번 서버 연결과 서버·DB 정상 응답도 확인했다.
- 운영 배포·PR·휴대폰 설치는 수행하지 않았다. 실제 계정 진단·건강정보를 저장하거나 삭제하지 않았다.
