# 2026-10-16 배포용 앱 통합

이전 앱 통합 PR #21 이후 로컬에서 작업한 변경을 `AI-HealthCare-05/dangno-life-devday-2026`의 `main` (`d41a788`)에 통합한다. 병합 대상은 `main`이고, 앱 이름은 **간당간당(배포)**, Android ID는 `life.dangno.app.deployment`, API는 `https://www.dang-no.life`다. 기존 로컬 앱 `life.dangno.app`과 계정·저장소를 분리한다.

## 최종 변경 사항

### 건강정보·진단 기록

- 당뇨병 진단 응답을 별도의 날짜별 기록으로 저장한다. 원래 건강정보에서 다시 기록하면 원래 날짜·기록 ID를 유지하며 이용확인부터 시작한다.
- 진단을 ‘예’로 선택하거나 새 기록을 시작하면 건강정보 입력·분석 탭을 막고, 저장된 진단 날짜의 신규 예측·분석과 과거 결과/SHAP 조회도 서버에서 차단한다. 대시보드·예측 목록에서도 해당 날짜 결과를 제외한다.
- 진단 내역을 다시 기록하거나 삭제할 수 있다. 정정·삭제한 답변을 과거 이용확인 내역 가져오기가 다시 활성화하지 않는다. 원래 분석·건강정보 데이터는 삭제하지 않는다.
- 내역에는 진단 카드만 표시하고 같은 날짜 또는 연결된 건강정보 카드·수치는 렌더링하지 않는다. 다른 날짜 기록은 유지하고 표시 건수·페이지 나누기도 같은 기준을 사용한다.
- 기록 카드·원형 화살표 배경을 흰색으로 통일하고 굵고 둥근 SVG 화살표를 사용한다. 클릭·키보드 펼침/접힘과 모션 감소 설정을 유지한다.
- 건강/경제 만족도·삶의 질 입력에 본인이 느끼는 주관적 만족도이며 동년배와 비교해 기록하는 항목임을 설명한다. 보상 안내 문구의 대비도 보정한다.

### 선택 입력 보상·계정 지갑

- 검증된 선택 건강정보 17개 항목에 대해 항목당 당근 100개를 계정별 1회 지급한다. 학력 중복 입력, 0·없음 값, 수정·삭제·재입력, 동시 재시도와 동의·소유권을 검사한다.
- 선택 입력 칸에 가로 당근 표시·최초 안내·입력 완료 주황색 표시를 추가하고 분석 진행 중 실제 지급 합계·항목·계정 잔액을 보여준다.
- 서비스·숲·챌린지의 잔액 기준을 `UserWallet`로 통일한다. 지갑 응답 버전으로 과거 응답의 잔액 덮어쓰기를 막고 계정별 코디·배치를 보존한다.
- 음료·식단·운동은 분야별 하루 10개, 모두 완료하면 추가 50개를 지급한다. 표준 3개 기준 합계 80개이며 저장 실패·검토 대기에는 지급하지 않는다.
- 식단은 ‘당근밭에 비료를 주었습니다’, 운동은 ‘당근밭의 잡초를 뽑았습니다’를 안내한다. 서비스 V3·숲 V2가 같은 날짜/분야 지급 키를 사용해 재인증·재진입·화면 전환 중복을 막는다.
- 숲 활동의 고정 금액·서버 영수증·요청 ID와 기존 계정 이관을 적용한다. 기존 55개 지급 내역을 보존하며, 상자·수확 UI가 추가 당근을 중복 지급하지 않는다. 동물 출현 규칙은 변경하지 않는다.

### 챌린지·홈·사진 인증

- 챌린지가 없어도 홈에 저장된 승인 분석 결과가 표시되도록 갱신하고, 기록할 챌린지가 없으면 선택 화면으로 연결한다. 종료된 챌린지를 진행 중으로 취급하지 않는다.
- 정정된 과거 진단 안내·이전 선택 상태가 시작 버튼을 계속 막지 않도록 상태를 갱신한다. 현재의 긴급 증상·진단·동의 등 안전 차단은 유지한다.
- 모든 챌린지를 실천한 날은 ‘실천하지 못한 이유와 목표 조정’을 비활성화한다. 날짜·완료 상태 변경 시 다시 계산한다.
- 식사 인증은 음식명 분류와 분리한 음식·채소 면적 경로를 사용한다. CV 분할 면적과 VLM 의미 검토를 구분하고 불확실·면적 미달·검토 실패를 완료로 처리하지 않는다. 최종 확인과 재제출·보상 검증을 유지한다.
- 최신 main의 CPU CV 실행환경·공급 검증, 실패 이유 코드와 안내를 유지한다.

### 의료기관·위치

- Android 위치 권한과 iOS 사용 중 위치 설명을 추가하고 위치 거부·시간 초과 후 재시도/주소 검색을 지원한다. 새 위치 확인 실패 시 과거 위치로 응급의료기관을 재검색하지 않는다.
- 진단 안내의 의료기관 버튼은 독립 검색 대화상자를 열며 분석 화면으로 우회하지 않는다. 별도 ‘전화 문의 가능한 기관’ 버튼을 제거하고 결과에서 전화·지도 링크를 제공한다.
- 목록은 처음 5곳, 더보기를 누를 때마다 아래에 최대 5곳씩 추가한다. 기존 카드와 순서를 유지하며 더보기 자체는 위치/API를 재요청하지 않는다. 새 검색·실패·빈 결과에서 이전 목록을 초기화한다.
- 진단 안내 버튼의 가로 이탈·뒤로가기·닫기를 보정한다. 배포 통합 검증 중 큰 글자 확대 때문에 안내창 높이가 화면을 초과하는 문제도 보정했다.

### 숲·앱 패키징

- 입장 시 확인한 계정 닉네임을 렌더러 생성 전부터 사용하고 오래된 별칭·일시적 서버 실패가 이름을 바꾸지 않도록 한다.

- 집 안 전축 이미지를 포함하고 누락 텍스처를 만들지 않아 최초 진입·초기화 때 검정/초록 사각형이 잠깐 나타나는 문제를 막는다.

- 혈당이 A안 아이콘을 Android·iOS 리소스에 적용하고 원본 디자인과 재생성 도구를 포함한다.
- 최신 main의 iOS 숫자 생년월일, iOS 전용 CSS·실시간 개발 도구, 로고 인트로 다시보기, 다운로드 버튼, 웹/모바일 세션·숲 복귀 안전 검사를 유지한다.

## 서버 반영 순서

앱 APK와 서버 코드를 같은 릴리스로 갱신해야 새 진단·지갑·선택 입력 보상 API를 사용할 수 있다. 이 PR 생성 자체가 운영 서버를 재시작하거나 배포하지는 않는다.

1. 운영 DB를 보호된 위치에 백업하고 서버의 기존 환경변수·모델 마운트를 유지한다. 백업을 Git·APK에 넣지 않는다.
2. 병합된 커밋을 체크아웃하고 `python restore_workspace.py`로 소스를 복원한다. 수정 중인 운영 파일 위에 덮어쓰지 않는다.
3. MySQL 등 비데모 DB는 서버 환경에서 `aerich upgrade`로 `28_20261016090000_editable_diagnosis_records`까지 적용한 뒤 `python scripts/backfill-diagnosis-records.py --apply`를 실행한다. 기존 이용확인의 진단 응답을 반복 실행에 안전하게 이관한다. SQLite 데모 경로는 기존 스키마 생성과 시작 훅에서 이관한다. 롤백 시 진단 기록 테이블을 삭제하지 않는다.
4. 서버 이미지와 웹 정적 파일을 같은 커밋으로 배포하고 프로세스를 재시작한다. `.env.example`은 변수 이름만 제공하며 실제 키/경로/설정은 서버에서 유지한다.
5. 카카오 일반 기관 검색은 `MEDICAL_FACILITY_SEARCH_PROVIDER=kakao`, `KAKAO_REST_API_KEY`, `KAKAO_JAVASCRIPT_KEY`를 준비한다. JavaScript 키의 도메인에 배포 주소와 네이티브 WebView `https://localhost`를 별도로 등록한다. 응급기관 조회에는 별도 `NEMC_SERVICE_KEY`가 필요하다.
6. 승인 모델·CV와 오늘이 SHAP Train 기준표본을 보호된 아티팩트 경로에서 준비한다. [오늘이 점검·복구 순서](../model/TODAY_XAI_LOCAL_DEPLOYMENT_AUDIT_20261014.md)와 [팀 파일 전달 안내](TEAM_HANDOFF.md)를 따른다. 기준표본은 Git/공개 정적 파일/APK에 포함하지 않는다. 기존 unavailable 결과를 조회만 해서는 설명이 재계산되지 않는다.
7. `/health`, `/api/v1/ready`, 인증 없는 새 `/api/v1/forest/wallet`·`/api/v1/health-input-rewards`의 401 응답과 OpenAPI를 확인한다. 합성 테스트 계정으로 진단 정정·삭제, 지갑, 새 분석, 사진 최종 확인까지 점검한다.
8. [Android 가이드](ANDROID_DEVICE_GUIDE.md)의 `pnpm build:mobile:deployment` → `cap sync android` → Gradle `-PmobileDeployment=true`로 새 APK를 설치한다. iPhone은 [유지된 iOS 가이드](IOS_DEVICE_GUIDE.md)에 따라 Mac/Xcode에서 같은 배포 번들을 빌드·서명한다.

## 별도 준비 파일

APK, 서버 모델 바이너리, 오늘이 `background.csv`, CV 모델, `.env`·API 키, 사용자 DB/사진·의료 원자료, 서명키와 제작자 고양이 원본 팩은 PR에 넣지 않는다. 공개 Git에는 코드·마이그레이션·테스트·안내·배포 가능한 디자인 자산만 포함한다. 모델 registry와 기준표본 manifest는 원본 행을 포함하지 않는 메타데이터다.

팀 배포 빌드는 기존 복원 아카이브나 개발 PC에 남아 있는 `licensed-kittens` 원본도 APK에 넣지 않도록 제외한다. 없는 팩에는 기존 펫 대체 그림을 사용하며 개발자의 원본 파일은 삭제하지 않는다. 개인 로컬 빌드 동작은 유지한다.

## 검증 범위

통합 테스트는 실제 이용자 계정/기록과 분리한 합성 입력·메모리 DB·모형 API를 사용한다. Android는 최신 HTTPS 번들을 사용한 전체 Gradle 빌드로 확인한다. iOS 변경은 기존 main을 보존하고 관련 Node 테스트로 회귀 검사했으나 Windows에서 Xcode 빌드·서명·실기기 테스트는 수행하지 않는다. 실제 운영 서버 로그인·모델·사진 인증 성공 여부는 운영 배포 후 확인해야 한다.

- 통합 서버 검사 **289개**, 별도 진단 마이그레이션 **2개**, 모바일·숲·관련 프런트 회귀 **509개**, 사진 화면 **18개**가 통과했다. 실행 범위가 겹치는 검사들은 고유 테스트 총수로 합산하지 않는다.
- 통합 화면에서 진단 안내·건강정보 숨김·흰색 카드·의료기관 5곳씩 더보기 **9개 시나리오**, 숲 지갑 브라우저 시나리오를 통과했다. 실패 저장=100 → 식단=110 → 운동=120 → 전체 완료=180 → 재진입=180으로 중복 보상이 없었다.
- `app`/`ai_worker` Ruff 검사와 Android `assembleDebug -PmobileDeployment=true`가 통과했다. 이는 네이티브 전체 빌드이며 기존 APK에 웹 파일만 교체한 방식이 아니다.
- 전체 프런트 단위 검사 **224개 중 214개 통과, 10개 실패**가 남았다. 동일 실패 10개가 변경 전 `main` 소스로도 재현됨을 별도 복사본에서 확인했다. 구 챌린지 추천·후속 안내 하네스 4개, 이전 숲 API/저장 계약 4개, 과거 일일 기록 상태 하네스 2개다. 성공한 새 기능 검사와 전체 검사 상태를 구분하고 PR은 Draft로 제출한다. 통합 중 새 의존성을 반영하지 못했던 테스트 하네스는 고쳤지만 나머지 기존 계약을 임의로 약화하지 않는다.
- Python 검사에는 기존 Starlette 상태 상수 deprecation과 Windows 하위 프로세스 콘솔 인코딩 경고가 있다. 테스트 실패와 구분한다. 실측 메모리·FPS의 새로운 개선 수치는 측정하지 않았다.

이전 작업 문서의 ‘로컬만 적용’·당시 APK 해시·설치 시각은 과거 검증 기록이며, 이번 통합 소스와 설치물은 이 문서를 기준으로 한다.
