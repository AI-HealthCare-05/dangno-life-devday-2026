# App 통합 — main 대비 최종 변경사항

병합 대상은 `AI-HealthCare-05/dangno-life-devday-2026:main`, 최초 준비 기준은 `f87233c`, 최신 앱 패치 비교 기준은 `5017d3f`이다. 이전 저장소의 앱 작업 (`020f13b`)과 2026-10-09까지의 로컬 수정 내용을 반영한다. 대상 저장소는 분할 압축본과 후속 패치를 복원하는 구조이므로 아래 내용은 **복원된 main과 비교한 기능 차이**다. PR에서 처음 추적하는 전체 소스 파일의 줄 수를 전부 신규 기능으로 해석하지 않는다.

## 앱과 실행 환경

- Capacitor 8.5.2, Node 22 이상, pnpm 11.19.0으로 웹 화면을 Android/iOS 프로젝트에 패키징한다. Android 최소 API 24, SDK 36, JDK 21; iOS 최소 15, Xcode 26 및 Swift Package Manager.
- API 주소를 빌드 때 지정하고 `/forest`, `/service`를 번들 페이지로 변환한다. 네이티브 카메라·사진 선택·업로드, 시스템 여백, 뒤로가기 이력을 연결하고 웹 서비스 워커의 오래된 캐시를 네이티브에서는 사용하지 않는다.
- 로컬 앱 `life.dangno.app`/간당간당과 배포 앱 `life.dangno.app.deployment`/간당간당(배포)을 분리하여 동시에 설치한다. 배포 앱은 `-PmobileDeployment=true`와 HTTPS 서버용 번들로 빌드한다. 계정과 데이터도 별도다.
- `pnpm build:mobile:deployment`는 같은 최신 소스를 기본 `https://www.dang-no.life`에 연결하며 HTTP 주소를 거부한다. 로컬 빌드 명령은 유지한다.
- 독립 SQLite 로컬 API, 설정·모델/CV 준비·서버 시작/중지·BlueStacks 연결·진단 도구를 추가한다. API 주소가 루프백일 때만 로컬 HTTP를 허용한다.
- Python 실행기 복구와 SQLite 차단 진단, 기존 공식 Python 우선 선택을 제공한다. 시스템 보안 정책을 자동 해제하지 않는다.

## 서비스 화면·인증·이동

- 모든 페이지에서 최신 서비스 경로를 유지한다. 숲 바로가기/서비스 홈으로 이동할 때 로그아웃되거나 구버전 화면이 열리는 경로를 정리한다.
- 숲은 로그인 필수이며 로그인·회원가입 후 요청한 숲으로 돌아간다. 같은 탭의 sessionStorage 전달 값은 서버에서 검증한다. 토큰을 URL이나 localStorage에 넣지 않는다. 계정 만료와 서버 연결 실패를 구분한다.
- 로그인/회원가입 영역은 화면 폭에 맞추고 마이페이지는 오른쪽에 배치한다. 숲 A안 글자 버튼은 로고 아래에 두며 기존 글자 크기 선택을 유지한다.
- 로그인 중에는 인트로를 자동 재생하지 않고 마이페이지에서 다시 볼 수 있다. 인트로 스크롤, 드롭다운 버튼 형태, 공통 탭과 건강정보 하위 탭 겹침을 보정한다.
- 앱 뒤로가기는 직전 페이지로 이동한다. 숲 플레이 중에는 “서비스 홈 화면으로 나가시겠습니까?” 확인 후 이동한다.
- 건강도구·건강정보 카드의 가로 넘침, 자연스러운 줄바꿈, 분석 준비 문구 이탈, 결과 게이지 비율, 홈 알림 버튼과 카드 여백을 조정한다.

## 건강정보·오늘이/내일이·SHAP

- 이용확인 답변을 건강정보 기록과 함께 저장·복원한다. 분석 탭에서 이전 분석 완료 안내 대신 저장된 분석 결과를 보여준다.
- OCR은 건강정보 입력에서 동의 → 추출 미리보기 → 사용자 확인 → 입력란 반영 → 저장 순서로 이용한다.
- 불필요한 결과 범주 박스와 개별 요인 상세보기를 제거한다. 결과 그림 아래 모델 수치를 자세히 보는 토글, 설명 박스 하단의 전체 SHAP 그래프 토글을 제공한다. `main`에 이미 있는 수치/SHAP UI를 통합하며 중복 ID를 제거한다.
- 오늘이 XAI의 Train 전용 참조 배경·출처/체크섬·승인 및 가산성 검증을 유지한다. 양/음의 SHAP와 영향 크기를 구분하고 입력값·비교 기준을 표시한다. 음주 없음이라는 입력 자체를 위험 원인으로 단정하지 않는다.
- 점수와 확정 발병확률을 구분하고 결과는 위험 선별·건강교육으로 표현한다. 승인된 근거가 없으면 설명을 임의로 만들지 않는다.

## 당근의 숲과 성능

- Canvas 렌더링, 아바타 프레임·투명 영역·옷장 미리보기·프리셋 복원을 보정한다. 최초 진입 시 잘못된 이동 수단 그림과 위아래 여백, UI 숨기기 때 화면 밀림을 수정한다.
- 숲을 전체 화면으로 배치하고 상단 설정·서비스 홈, 하단 인게임 탭과 반투명 조이스틱을 제공한다. 달리기는 버튼 토글이며 속도 슬라이더는 없다. 사용자 이름을 눌러 서비스 화면으로 이동하던 동작을 제거한다.
- 먹이주기는 잔액과 펫 반응만 갱신하고 가구를 재생성하지 않는다. 배치 상태가 같은 가구와 같은 아바타 합성 프레임/투명 영역 검사 결과를 재사용한다.
- 정지 썸네일을 120ms마다 다시 합성하지 않는다. 같은 코디·프레임·크기의 미리보기를 최대 4 MiB의 캔버스 픽셀 캐시에 보관하고, 제거 시 버퍼를 해제한다. 숨겨진 코디·창고·모임 목록은 그리지 않는다.
- 집·당근밭 전환에서 전체 창고/코디를 갱신하지 않는다. 이미지 로딩 이벤트를 한 프레임으로 모으고 독립 자산을 병렬 준비한다. 문서가 숨겨지면 미리보기 루프를 쉬게 한다.
- S25 실측: 저장 코디 목록 1.63–1.98초 → 반복 4.4–7.2ms, 집 진입 약 2.46초 → 112.9ms, 당근밭 진입 약 2.56초 → 117.4ms. 꾸미기 창 rAF 간격 중앙값 약 466–483ms → 8.3ms. 최초 카테고리 합성 등의 비용은 남아 있다. [측정 방법·전체 결과·한계](FOREST_PREVIEW_PERFORMANCE.md).

## 챌린지·사진 인증

- 인증 항목을 세로 배열하고 완료/실패 안내를 화면 중앙에 표시한다. 미실천 이유의 기록하기에도 완료 안내를 연결한다. 검토 실패를 완료로 표시하지 않는다.
- 로컬 음식 CV 실행·Drive 공급 계약·체크섬·CPU 의존성·판정 오류를 보완한다.
- 김치·진한 양념·흰 음식/흰 식기의 조건을 `있음/없음/잘 모르겠음`으로 입력받는다. CV 불확실·임계값 근처·취약 조건에서 선택적으로 OpenAI VLM이 사진의 의미와 경계/품질을 보완 검토한다.
- VLM은 분할 마스크나 면적 기준을 대신하지 않는다. CV 기준 미달·불확실, VLM 충돌/실패는 보류한다. 같은 사진과 체크 답변의 최종 확인이 있어야 기록되며 중복 보상을 막는다.
- `OPENAI_API_KEY_FILE`은 로컬 경로만 설정하고 서버 메모리에 키를 주입한다. 키·사용자 사진·건강정보는 Git/앱에 넣지 않는다. 공개 사진 비교 수집/평가 도구는 학습 데이터와 별도이며 결과는 `outputs/`에만 저장한다. [구현·검증·제한](../model/FOOD_PHOTO_VLM_SUPPLEMENT_20261009.md).

## 이 저장소 통합과 팀 전달

- `main`의 팀 문서, 서버/RAG 후속 변경, 웹 Android 다운로드 진입점을 유지한다. 기존 Android 다운로드 작업은 외부 저장소의 오래된 고정 커밋 대신 이 저장소의 해당 커밋을 빌드한다. PR 모바일 회귀 검사 워크플로를 추가한다.
- 복원기는 체크섬을 검증한 압축본을 복원하면서 Git에서 추적하는 깨끗한 최신 소스를 우선한다. 수정 중인 파일은 거부한다. Windows 줄바꿈에서도 패치 검증이 동작하도록 하고 복원 회귀 테스트를 추가한다.
- [Android 가이드](ANDROID_DEVICE_GUIDE.md), [iPhone 가이드](IOS_DEVICE_GUIDE.md), [별도 전달 파일/서버 준비](TEAM_HANDOFF.md), [공통 체크아웃·실행](README.md)을 제공한다. 모델·XAI 배경·CV 파일은 승인된 Drive 경로에서 별도 준비한다.
- APK·IPA, 개인 서명키, API 키, `.env.local-mobile`, 실제 사용자 SQLite, 의료 원자료, 모델 바이너리, 공개 사진 실험 원본·결과는 PR에 포함하지 않는다. 제작자 고양이 원본 팩도 별도 설치 대상으로 Git에서 제외한다.

## 검증 한계

최신 main의 숲 복귀 안내·공통 디자인 토큰·첫 화면 모바일 다운로드 표시도 통합했다. 숲 복귀는 서버의 현재 동의·이용 가능 상태를 읽기로 확인하는 기존 비동기 검증을 유지하고, 잘못된 사유 코드도 이동을 차단한다. 네이티브 앱 안에서는 다운로드 바로가기를 숨긴다.

숲 복귀 안전 검사 4개, 최신 main의 웹·모바일 계정 복원 검사 3개와 흡연 입력값을 포함한 XAI 검사 9개도 통과했다. 최신 main의 사용자·IP·서버 로그는 가져오지 않고 앱 패치만 선택하여 통합했다.

이번 통합 검사에서 숲 JavaScript 375개, 모바일 통신/패키징 및 성능 29개, 사진 화면 14개, 숲/소스 복원 Python 58개, API·CV/VLM·설정·XAI Python 139개가 통과했다. 전체 `app`/`ai_worker` Ruff 검사도 통과했다. 위 목록에는 중복 실행한 성능 테스트가 있으므로 합산한 개수를 고유 테스트 수로 제시하지 않는다.

전체 프런트엔드 검사에는 오래된 챌린지 추천·선택·숲 API·일일 기록 하네스 실패 14개가 남아 있으며 원래 로컬 소스에서도 동일하게 재현했다. 성공한 해당 기능의 실제 사용자 흐름과 이 오래된 하네스의 상태를 구분한다. 이번 PR의 자동 검사는 모바일·성능·사진 및 소스 복원에 초점을 맞춘다.

2026-10-09 `https://www.dang-no.life/health`는 200, `/api/v1/ready`는 503이었다. 서버 전체 준비 완료나 실제 계정 로그인/건강정보 분석/사진 제출 성공을 이번 접속 검사로 주장하지 않는다. PR을 올리는 작업은 운영 서버의 코드·모델·환경변수를 배포하는 작업과 별개다.

이번 배포용 APK는 기존 배포 앱의 네이티브 바이너리에 새 HTTPS 웹 번들을 넣어 재서명했다. 이름·패키지·원본과 같은 인증서·번들 파일 일치를 검증했으며 전체 Gradle 재빌드는 아니다. Git에는 재빌드 가능한 네이티브 프로젝트와 해당 커밋을 빌드하는 워크플로를 포함한다.

이전 Android/BlueStacks/S25 실기기 검증과 이번 통합 소스 회귀 검사는 구분한다. 최근 S25 수정본은 기존 네이티브 바이너리에 웹 번들을 갱신한 것으로 전체 Gradle 재빌드가 아니었다. iOS 컴파일·서명·실기기 검증, Health Connect/HealthKit 실제 연동, OS 알림·백그라운드 동기화, 스토어 배포는 미완료다. 배포 서버의 모델/CV 준비 상태는 팀이 별도로 확인해야 한다.
