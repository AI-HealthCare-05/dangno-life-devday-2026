# 분석 완료 후 홈 표시와 챌린지 진입 점검 (2026-10-16)

## 원인

- 로그인 복구 시 진행 중인 챌린지 조회가 404이면 홈 요약 조회까지 건너뛰었다. 저장된 `오늘이` 분석이 있어도 최근 위험 범주가 초기값 `-`로 남았다.
- 진행 중인 챌린지가 없는 상태에서 홈의 `오늘 기록하기` 또는 챌린지 탭은 빈 기록 화면만 열었다. 선택 화면으로 가는 경로가 눈에 띄지 않았다.
- 분석 완료 직후에도 홈 요약을 다시 읽지 않아 같은 세션에서 이전 표시가 유지될 수 있었다.
- 과거 진단 응답을 정정하고 활성 진단 기록을 모두 없앤 후에도 예전 미확인 진단 안내가 챌린지를 차단했다.

## 변경

- 챌린지 조회와 홈 요약 갱신을 분리하고, 챌린지가 없어도 승인된 `오늘이` 결과와 오늘 할 일 상태를 표시한다.
- 분석 완료 직후 홈 요약을 갱신한다.
- 진행 중인 챌린지가 없다면 챌린지 탭과 홈의 기록 버튼이 선택 화면을 연다. 후보 API를 기다리는 동안에도 화면과 로딩 안내를 먼저 표시한다.
- 인트로 다시보기 화면의 별도 앱 스크립트에도 동일한 흐름을 적용한다.
- 이후 명시적인 진단 ‘아니요’ 응답이 있고 활성 진단 기록이 없는 경우, 이전 이용확인에서 생성된 진단 안내를 현재 차단 대상으로 취급하지 않는다. 이력과 실제 확인 시각은 변경하지 않는다. 긴급 증상 안내·활성 진단 기록·최신 진단 ‘예’는 계속 유지한다.
- `terminated` 상태의 이전 챌린지는 진행 중인 챌린지로 취급하지 않는다.

위험 범주는 서버가 승인하여 공개한 결과만 표시한다. 예측 결과는 진단이나 처방이 아닌 위험 선별 정보다. 진단·긴급 증상 등 기존 이용 제한은 그대로 적용한다.

## 검증

- `tests/frontend/challenge_selection_entry.test.cjs`에서 챌린지가 없는 승인 결과의 홈 표시, 후보 조회 지연 중 선택 화면 진입, 챌린지 조회 오류 처리 확인.
- `node --check`로 두 화면 스크립트의 문법 확인.
- 챌린지·진단 API 회귀 테스트 70개 통과. 정정 후 실제 새 챌린지 생성, 미정정 진단과 긴급 안내의 차단 유지 포함.
- 가짜 계정 응답만 사용한 Chrome 확인에서 390px·1024px 모두 홈의 저장된 오늘이 범주, 챌린지 선택 화면, 시작 버튼 활성화 확인.
- 로컬 Android APK 빌드 후 BlueStacks 기존 `life.dangno.app`에 데이터 보존 방식으로 설치·실행. 개인 계정의 챌린지 시작 API 쓰기는 자동화하지 않았다.
- 로컬 계정의 저장된 승인 결과와 현재 차단 안내가 없음을 읽기 전용으로 확인했다. 과거 미확인 안내는 감사 이력에 보존했다.

## 실행 서버 반영 재확인

- 앱에서 시작 버튼이 계속 비활성화된 후속 제보를 WebView 디버깅으로 확인했다. 선택 수는 3개였으나 실행 서버의 `follow-up-actions` 응답에는 신규 `blocking` 필드가 없었다.
- 이전 서버의 재로딩 부모 프로세스가 종료되고 오래된 자식 서버만 남아 소스 변경을 읽지 않고 있었다. 해당 로컬 서버만 같은 DB·설정으로 재시작했다.
- 실제 앱 API에서 과거 진단 안내의 `blocking=false` 응답을 확인한 후 후보를 다시 조회했다. 로그인과 선택 3개를 유지한 상태에서 안내 패널 숨김·차단 안내 0개·시작 버튼 `disabled=false`를 확인했다. 실제 계정의 챌린지 생성은 실행하지 않았다.
