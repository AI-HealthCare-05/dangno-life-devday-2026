# 챌린지 전체 완료 시 이유·목표 조정 비활성화

2026-10-15. 로컬 `app.js`와 `intro-retro-app.js`에 동일하게 적용했다.

- 오늘 진행 중인 챌린지의 **모든 ID가 오늘 완료 집합에 있을 때** 챌린지 선택·이유 선택·기록 버튼을 함께 비활성화한다. 다른 회차의 오래된 완료 ID 개수로 전체 완료를 판단하지 않는다.
- 폼을 흐리게 표시하고 “오늘의 챌린지를 모두 실천했어요. 이유와 목표 조정은 필요하지 않아요.”를 표시한다. 이전 목표 조정안은 숨긴다.
- 완료를 취소하거나 다음 날 기록을 새로 불러와 미완료가 있으면 다시 활성화한다. 기록 조회 중·조회 오류·진행 중인 챌린지 없음 상태에서는 이유 기록을 막는다.
- 화면의 제출 함수를 직접 호출해도 전체 완료 상태이면 저장 요청을 보내지 않는다. 저장 중 마지막 챌린지를 완료하거나 계정·회차를 바꾼 경우 늦은 응답으로 조정안을 다시 열지 않는다. 폼의 저장 중 상태를 복원할 때도 완료 상태를 다시 적용한다.
- 서버 API의 데이터·보상 규칙은 변경하지 않았다. 이번 검증에서 사용자 완료 기록·이유·보상을 생성하거나 취소하지 않았다.

## 검증

`barrier_record.test.cjs`, `barrier_availability.test.cjs`의 17개 테스트가 통과했다. 전체 완료, 부분 완료·취소, 다음 날 초기화, 오래된 ID, 조회 오류, 저장 중 완료, 계정·회차 변경과 요청 차단을 포함한다.

별도 브라우저 검증에서 일반·인트로 페이지를 390px·1024px로 확인했다. 합성 상태로 실제 `renderDailyRecordList`를 호출하여 세 컨트롤 비활성화·안내 표시·제출 요청 0회·완료 취소 후 재활성화를 검증했다. 실제 API 호출은 차단했다. 검증 기록은 상위 `outputs/barrier-disable-20261015`에 있다.

확장 회귀 테스트에서는 기존 3개 실패도 확인했다. 이번 수정 전 APK의 `app.js`를 사용해 동일한 실패를 재현했다. 이들은 기존 테스트의 API 응답 스텁(`wallet_reward`)과 일일 기록 부분 조회 실패·로컬 미리보기 ID 복원 처리에 관한 것으로 이번 변경에서 해결하지 않았다. 새 기능의 테스트 통과와 전체 회귀 테스트 통과를 혼동하지 않는다.

## 로컬 APK 반영

모바일 번들·Capacitor 동기화 및 Android 빌드가 성공했다. 블루스택 `life.dangno.app`에 기존과 같은 서명으로 데이터 보존 업데이트를 설치했다. API 주소는 `http://127.0.0.1:8000`이다.

설치된 앱에서 원래 메모리 상태를 보관하고 임시 완료 조건을 동기적으로 적용해 세 컨트롤 비활성화·안내·완료 취소 후 재활성화를 확인한 뒤 원래 상태로 복원했다. 기록 API를 호출하지 않았으며 로그인 유지와 숲 저장 해시 동일도 확인했다. 배포 서버·배포용 APK는 변경하지 않았다.

검증 APK: 상위 작업 폴더의 `outputs/barrier-disable-20261015/gandang-local-barrier-disabled.apk`.
