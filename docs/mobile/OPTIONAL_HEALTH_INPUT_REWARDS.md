## 화면과 지급 기준

- [공유 디자인 채팅](https://chatgpt.com/share/6ad06e1c-2994-83ee-a621-0068678af132)의 입력 칸 안에 가로로 누운 당근을 넣는 요청을 참고했다. 2026-10-16부터 공유 채팅에 첨부된 `pngtree-cute-carrot-illustration-png-image_8537848.png`와 바이트가 같은 원본을 `src/frontend/assets/optional-health-carrot-shared.png`로 사용한다. 원본의 표시와 워터마크를 편집하지 않고 SVG 표시 영역에서 55도 회전해 가로로 배치한다. 메인·인트로 화면에 공통 적용하며 앱 번들에 포함하므로 외부 이미지 서버 연결이 필요 없다.
- 현재 서비스 화면의 선택 항목 17개에 당근을 표시한다. 허리둘레·혈압 3개, 만족도·삶의 질 3개, 선택 진단 여부 5개, 가족력 2개, 학력·지역·가구 형태·가구소득 4개다. 구형 인트로 페이지에도 이 목록 중 존재하는 입력 항목에 적용한다.
- 표시된 선택 항목 하나당 100개를 지급한다. 금액은 서버 `CARROTS_PER_FIELD`에서 결정한다. 학력은 두 모델에 전달해도 한 항목으로 센다.
- 당근을 처음 누르면 “더 많은 건강정보를 입력하고, 더 높은 예측 결과를 받아보세요. 당근의 숲에서 사용할 수 있는 당근 100개는 덤!”을 표시한다. 안내 확인 여부만 브라우저에 계정별로 저장하며 건강정보 값이나 토큰은 이 기능의 저장소에 쓰지 않는다.
- 입력 전에는 가로 당근을 보여 주고 클릭하면 입력할 수 있다. 유효한 값을 입력하면 칸을 주황색으로 표시한다. 0과 ‘없음’도 알려진 응답이다. 빈 값·모름·응답 어려움·범위 오류는 보상에서 제외한다.
- 2026-10-16: ‘선택 정보 …개 입력 · 예상 당근 …개’ 안내는 크림색 배경(`#fff5dc`)과 진한 갈색 글자(`#422b17`)를 사용한다. 나무 배경에서도 대비를 유지하며 작은 화면에서는 줄바꿈한다. 메인·인트로 화면에 공통 적용한다.
- 실제 브라우저의 메인·인트로 화면, 390px·1024px에서 계산된 전경/배경 대비 12.17:1과 가로 이탈 없음을 확인했다. 확인 화면은 상위 `outputs/diagnosis-edit-20261016/readable-notice-*.png`에 보관한다.
- 허리둘레·혈압의 초기 예시 숫자를 제거했다. 저장된 본인 기록을 불러오는 동작은 유지한다. 세 입력의 범위도 기존 서버 계약과 일치시켰다.
- 같은 계정은 같은 항목에 한 번만 보상받는다. 수정, 지우기, 재입력, 새 건강기록, 재분석, 다른 기기와 삭제 후 재작성으로 보상을 다시 받을 수 없다. 기존 기록의 알려진 선택 값은 다음 분석 시 한 번 보상받을 수 있다.

## 분석 중 지급 확인

- 건강정보와 현재 건강정보 스냅샷을 저장한 뒤 분석 요청과 함께 서버 보상 확인을 시작한다. 클라이언트의 예상 개수를 실제 지급으로 처리하지 않는다.
- 분석 진행 카드 위에서 실제 지급 합계·현재 계정 잔액을 표시하고, ‘지급 항목 자세히 보기’로 항목별 지급 내역을 펼칠 수 있다.
- 보상은 정보 저장을 기준으로 한다. 모델 계산의 성공 여부나 위험 점수에 따라 금액이 달라지지 않는다. 예측 입력·모델 가중치·임계값은 변경하지 않았다.
- 지급 API 실패 시 분석은 계속되고 보상 확인 실패와 재확인 버튼을 표시한다. 서버에 반영된 뒤 응답만 끊긴 경우 재확인으로 같은 기록의 지급 합계를 읽으며 다시 지급하지 않는다.

## API와 저장

- `GET /api/v1/health-input-rewards`: 로그인한 본인의 지급 대상 목록·항목별 수령 여부. 건강정보 값이나 토큰은 반환하지 않는다.
- `POST /api/v1/health-input-rewards/claim`: `checkup_id`, 선택적인 `current_screening_input_id`만 받는다. 클라이언트가 금액·보상 항목을 지정할 수 없다.
- 현재 유효한 건강정보 동의, 건강기록 소유권, 스냅샷의 소유권과 부모 기록 일치를 확인하고 저장된 값에 기존 DTO 검증을 적용한다.
- `UserWallet`과 `RewardTransaction`을 사용한다. 지급 키는 `optional-health:<user_id>:<field_key>`다. 기록 ID와 필드 키만 영수증에 남기고 건강정보 원문은 남기지 않는다.
- 지갑 잠금과 영수증 저장은 같은 트랜잭션에서 처리한다. 지급 도중 실패하면 전체 지급이 취소된다. 스키마 마이그레이션은 없다.
- 숲의 계정 지갑과 같은 잔액을 사용한다. 기존 가입/숲 환영 보상 100개는 선택 입력 보상 합계에 포함하지 않는다.
