# S25 앱 지연 점검 — 2026-10-09

## 환경과 방법

- 실제 S25(SM-S931N)의 로컬 앱 `life.dangno.app`, API `http://127.0.0.1:8000`. 앞서 적용한 먹이주기·가구 재사용·아바타 프레임 캐시 수정본이다. 사용자가 먹이주기 지연 해소를 확인했다.
- WebView에서 실제 메뉴 이벤트를 실행하고 동기 처리 시간과 다음 `requestAnimationFrame`까지 시간을 기록했다. 후자는 화면 전체가 완전히 표시된 시간이나 서버 작업 완료 시간이 아니다.
- 숲 메뉴 64회와 CPU 샘플링을 함께 측정한 뒤, 프로파일러 없이 옷장·저장 코디 목록을 15회 추가 검사했다. 집·당근밭·LP 목록 8개 동작과 서비스 조회 탭도 검사했다.
- 메뉴가 열린 동안의 프레임 간격을 별도로 기록했다. CPU 샘플링은 원인 확인용이며 휴대폰 전체 CPU 사용률로 해석하지 않는다.
- 추가로 앉기 토글, 헤어·상의·펫 미리보기 9개 동작을 검사했다. 구매나 코디 저장 없이 잔액·코디·앉기 자세가 유지됨을 확인했다.
- 구매·보상 수령·코디 저장·챌린지 인증 제출·건강정보 저장은 실행하지 않았다. 전체 검사 후 숲으로 돌아왔다. 메뉴 검사에서 잔액 및 저장 코디가 유지됨을 확인했다.

## 확인된 원인

### 1. 꾸미기 창에서 작은 그림까지 반복 합성

`forest-game.js`의 `animateWorld()`는 꾸미기 창이 열려 있으면 120ms마다 `renderCatalogThumbnailCanvases()`와 `renderAvatarPreview()`를 함께 호출한다. 몸·머리·옷 등 정지된 상품 미리보기까지 계속 합성한다. CPU 프로파일에서도 `renderCatalogThumbnailCanvases()`가 주요 비용으로 확인됐다. 검사 당시 기본 카테고리의 작은 캔버스는 4개였는데도 프레임 간격이 약 0.5초였다.

우선 작은 미리보기는 카테고리·드래프트·이미지 로딩 상태가 바뀔 때만 갱신하고, 애니메이션은 큰 아바타/펫 미리보기에 한정하는 것이 적절하다. 동일한 조합은 크기를 제한한 썸네일 캐시를 사용할 수 있다.

### 2. 저장 코디 그림을 숨겨진 목록까지 다시 그림

`renderInventoryDialog('wardrobe')`는 목록을 만든 뒤 `drawWardrobeLookThumbnails()`를 호출한다. 이 함수는 `document.querySelectorAll('canvas[data-outfit-canvas]')`로 문서 전체를 조회한다. 실제 저장 코디는 6개, 대화상자와 숨겨진 목록을 합치면 캔버스 12개였다. 목록을 열 때마다 두 목록을 모두 합성해 약 1.6–2초 지연이 반복됐다.

표시 중인 목록으로 조회 범위를 제한하고, 저장 코디가 변경되지 않았으면 이미 생성된 미리보기를 재사용하는 개선이 필요하다.

### 3. 집·당근밭 전환에서 창고/코디까지 갱신

`switchScene()`는 장면을 바꿀 때 `renderInventory()`를 호출한다. 이 함수는 숨겨진 코디 목록·창고 목록을 만들고 그림을 그린다. 장면 이동에는 해당 목록을 다시 합성할 필요가 없으며, 이 경로가 장면 전환의 큰 동기 작업으로 연결돼 있다.

장면·배치 상태·음악·수확 표시만 갱신하고 코디/창고는 실제 내용 변경 시 갱신하는 방식이 적절하다.

### 4. 숲 재진입의 초기화 비용

숲으로 다시 들어갈 때 캔버스 준비까지 약 4–6초가 반복됐다. 초기 `renderAll()`, 이미지 로딩 완료 시 반복되는 `renderInventory()` 및 `lpc-avatar-assets-updated`의 숨겨진 코디·모임 썸네일 갱신을 추가 최적화 대상으로 확인했다. 재진입 시간 전부를 특정 한 함수나 서버 지연으로 단정하지 않는다.

## 범위와 후속 우선순위

1. 꾸미기 창의 정지 썸네일 반복 갱신 제거.
2. 저장 코디의 숨겨진 그림 갱신 차단 및 썸네일 재사용.
3. 집·당근밭 전환에서 전체 코디/창고 갱신 제거.
4. 이미지 로딩 이벤트를 표시 중인 화면에 한정하고 숲 초기화 비용 재측정.

이번 작업은 점검이며 추가 최적화 코드를 적용하거나 커밋·푸시하지 않았다. 다수 가구가 배치된 상태, 장시간 플레이, 실제 전투/보상 발생, 사진·OCR 제출, 건강정보 분석 실행 시간은 이번 측정으로 검증하지 않았다.

원시 측정 자료는 Git 제외 경로 `outputs/mobile/forest-lag-audit.json`, `forest-lag-confirm.json`, `forest-lag-scenes.json`, `forest-lag-preview.json`, `service-lag-audit.json`, `forest-lag-navigation.json` 및 CPU 프로파일에 보관했다. 계정 이름·토큰·건강정보 원문은 측정 자료에 기록하지 않았다.

후속으로 위 네 가지 개선을 적용하고 S25에 설치해 재측정했다. 구현 내용·전후 결과·검증 한계는 [메뉴·장면 전환 성능 개선](FOREST_PREVIEW_PERFORMANCE.md)을 참고한다. 이 문서의 표는 수정 전 기준 측정으로 유지한다.
