# develop 대비 앱 최종 변경사항

비교 기준: 원격 develop 8364a21753fe5f55740423af92fc92af5f88e0ca. 앱 작업 브랜치 codex/local-mobile-development. 이 문서는 최종 소스 차이를 기록한다. 과거 작업 메모의 커밋·푸시 금지는 당시의 작업 상태이며 이번 PR 요청에 따라 변경사항을 공유한다.

## 앱 패키징과 실행

- 기존 웹 프런트엔드를 Capacitor 8.5.2로 묶는 빌드, pnpm lockfile, Android 프로젝트와 iOS Swift Package Manager 프로젝트를 추가했다. Android 최소 API 24/대상 SDK 36, iOS 최소 15.
- 빌드 시 API 주소를 지정하고 정해진 페이지 경로를 앱 내부 경로로 바꾼다. 로컬 HTTP는 loopback 개발 주소만 허용한다. 앱에는 프런트엔드 정적 파일만 복사하며 모델·DB·환경파일을 포함하지 않는다. 네이티브 앱에서 로컬 예측 미리보기와 웹 서비스 워커를 비활성화한다.
- API 전송, 카메라/갤러리 선택, 업로드 크기 제한, Android 뒤로가기와 페이지 이력 처리를 추가했다. 숲에서 뒤로가면 서비스 홈으로 나갈지 확인한다. 시스템 바와 화면 안전 영역을 고려한다.
- 별도 로컬 서버 시작/종료, SQLite 런타임 복구, CV와 모델 공급 확인, XAI 점검/재계산 도구를 추가했다. 환경파일 생성기는 독립 비밀키를 만들고 기존 파일을 덮어쓰지 않는다. 모델 배포 계약과 서버 실행 의존성을 기록했다.

## 계정과 공통 화면

- 서비스 경로가 최신 index 화면으로 연결되게 바꾸고 구형 suin 진입을 최신 화면으로 전환한다. 로그인 후 인트로를 건너뛰고 마이페이지에서 인트로 다시보기를 제공한다.
- 로그인/회원가입·마이페이지 위치와 공통 헤더를 조정했다. 당근의 숲 바로가기는 A안 글자 디자인을 사용하고 로고 아래에 배치했다. 기존 글자 크기 선택은 유지한다. 기본 글자 크기를 일괄 확대하지 않았다.
- 공통 메뉴와 건강정보 하위 탭을 별도 행으로 배치한다. 좁은 화면에서 카드·버튼·텍스트 이탈을 제한하고 한국어 줄바꿈, 단위, 게이지 비율을 수정했다. 알림 버튼은 카드 오른쪽 위로, 오늘 할 일 혈당이는 제목 오른쪽 위로 옮기고 큰 하단 여백을 제거했다. 인트로 스크롤 중 그림 배치를 안정화했다.
- 웹 페이지가 바뀌어도 로그인 access token을 sessionStorage의 제한된 세션으로 전달한다. URL과 localStorage에는 토큰을 넣지 않는다. 서버에서 세션 유효성을 확인하고 만료/철회 시 로그인으로 돌아간다. 연결 오류는 임의 로그인 성공으로 처리하지 않는다. 로그아웃 시 전달 세션을 제거한다.
- 당근의 숲은 로그인/회원가입 이후 이용하도록 진입 검사를 추가했다. 비로그인 바로가기는 로그인 후 요청한 숲으로 돌아가며 숲에서 서비스 홈으로 나와도 계정을 유지한다.

## 당근의 숲

- 네이티브 WebView의 아바타 렌더링 오류 대응으로 Canvas 렌더러를 사용하고 최초 진입/화면 변경 시 배경을 전체 화면에 맞춘다. UI 숨기기는 화면 구조를 바꾸지 않고 조작 표시만 전환한다.
- 방향 버튼을 반투명 드래그 조이스틱으로 바꾸었다. 달리기는 별도 토글 버튼으로 유지하며 속도 슬라이더는 없다. 포인터 취소·초점 상실 시 이동 입력을 해제한다.
- 상단 기능은 인게임 설정/HUD, 하단 기능은 간단한 인게임 탭으로 정리했다. BGM/음량·날씨/시간·글자 크기·확대/축소 동작을 유지한다. 서비스 홈 버튼과 나가기 확인을 추가했다. 사용자 이름은 페이지 이동 버튼으로 쓰지 않는다.
- 옷장 아바타 미리보기와 프리셋 표시를 조정하고 기존 코디 저장값을 유지한다. 로딩 직후 잘못 보이던 차량 대체 그림을 제거하고 관련 캐시 버전을 갱신했다.

## 건강정보·분석·SHAP

- 건강정보 관리에서 이용확인 기록을 복원하고 기존 분석 탭은 저장된 결과를 바로 연다. 분석 완료 대기 화면의 글자 이탈을 수정했다.
- 검진표 OCR을 건강정보 입력 단계로 옮겼다. 결과를 확인한 뒤 키/체중/허리둘레/수축기·이완기 혈압 입력란에 반영하며 최종 저장은 기존 건강정보 저장 절차를 따른다.
- 오늘이/내일이의 중복 위험 등급/승인 결과 박스를 제거했다. 그림 아래에 모델 분석 수치 상세보기 토글, 설명 박스 마지막에 전체 SHAP 그래프 상세보기 토글을 제공한다. 요인별 상세보기는 제거했다.
- 서버 응답에 모델 점수·임계값·SHAP 그래프와 실제 입력값 표시를 추가했다. 점수를 근거 없이 확률로 표시하지 않으며 SHAP의 양/음 기여를 인과관계로 설명하지 않는다. 음주 없음 등 입력값과 모델 배경 대비 기여의 차이를 구분한다.
- 오늘이 SHAP의 학습 참조 배경 공급/검증을 추가했다. Train 참조만 사용하고 모델·특징·전처리·체크섬 계약을 검증한다. grouped coalition 계산과 합산 검증으로 실제 모델 출력에 맞춘다. 한쪽 부호만 있는 결과도 허위 반대 요인을 만들지 않고 표시한다. 승인 모델 실행 제한은 유지한다.
- 모델 바이너리와 SHAP 배경 행은 Git에 포함하지 않는다. 로컬 기존 오늘이 XAI 재계산 도구는 별도로 제공한다.

## 챌린지·사진 인증

- 인증 항목을 세로로 배열하고 기록 완료 안내를 중앙에 표시한다. 실천하지 못한 이유 기록에도 저장 완료와 목표 조정 안내를 추가했다. 실패한 저장을 성공으로 표시하지 않는다.
- 사진 검토 결과를 확인하고 기록하는 절차와 중복 제출 방지를 조정했다. Windows CV 런타임 오류는 명확한 서비스 오류로 반환하고 서버 내부 예외를 사용자에게 노출하지 않는다. 검토 실패를 자동 인증 성공으로 바꾸지 않는다.
- 프로젝트 지정 Google Drive의 음식 CV 세 파일에 대한 다운로드/해시 계약과 CPU 실행 점검을 제공한다. OpenAI VLM 등 외부 공급자는 별도 환경 설정이 필요하다.

## 참고한 ‘당근의 숲’ 채팅

같은 작업 폴더의 변경사항이므로 별도 패치를 중복 적용하지 않았다. 해당 채팅의 아바타/조작/레이아웃 변경을 실제 develop diff와 대조했다. 이미 develop에 있는 가구·동물·촬영 기능은 이번 PR 신규 기능으로 기재하지 않는다. 당근 재화 조회는 읽기 전용 조사였고 잔액 통합을 구현하지 않았다.

남아 있는 제약: 숲의 기기 내 잔액과 서버 서비스 지갑/숲 아바타 잔액은 분리돼 있다. 숲 로컬 저장은 계정별 서버 영구 저장으로 전환되지 않았다. 일부 숲 로컬 인증/수확 이벤트가 서버 기록보다 먼저 진행되는 기존 경로가 남아 있다. 서버 저장 실패 시 로컬 완료/보상이 먼저 나타날 수 있으며 재화 통합·계정별 저장은 별도 수정 대상이다.

## 검증 및 검증 범위

- 변경 관련 Python 172개 통과(Starlette 상태 코드 명칭 경고 1개).
- JavaScript 전체 555개 중 539개 통과, 16개 실패. 아래 기존 검사 실패는 원격 develop 소스를 읽도록 동일 검사를 다시 실행해 모두 재현했다. 실패한 검사를 삭제하거나 성공으로 보고하지 않는다.
- 기존 실패 검사: forest-kitten-pack 1개(이미 추적된 licensed-kittens의 ignore 규칙 기대), challenge_selection_entry 4개(과거 단계/함수/문구), challenge_v3 4개(과거 함수 추출), forest_api_contract 4개(서버 저장으로 전환됐다는 과거 계약), saved_state 2개(과거 기록 계약), ui-color-system 1개(고정 CSS 버전).
- Android 빌드·BlueStacks 및 Galaxy S25 설치/레이아웃 검증을 수행했다. 마지막 인증 세션 전달은 브라우저 합성 계정으로 검증하며 실제 사용자의 로그인 계정 전체 시나리오를 이번 PR 준비 단계에서 재실행하지 않았다.
- iOS 프로젝트/권한/빌드 절차를 제공했으나 Windows 작업 환경에서 Xcode 컴파일·iPhone 설치는 검증하지 않았다. Health Connect/HealthKit 실제 동기화, 백그라운드 알림과 스토어 배포는 구현 완료 범위가 아니다.
- 현재 Android APK는 약 401 MiB이다. 공용 HTTPS API가 없으면 각자 서버를 준비해야 한다. 기본 dang-no.life의 현재 가용성은 이 문서가 보장하지 않는다.

## PR 자동 검사 수정 (2026-10-03)

- GitHub 최초 검사에서 Python 4개 실패와 Ruff 25개 오류를 확인했다. 승인 결과의 내부 모델 버전 표시는 제거하고 SHAP 영역의 접근성 이름은 공개 서비스 이름으로 정리했다.
- 프로필 갱신 검사는 실제 서버의 두 경로 계약을 확인한다. 인트로 로그인 복원 검사는 공통 세션 모듈의 refresh→서버 계정 검증 흐름을 확인한다. 기존 리다이렉트·건강정보 검사는 유지한다.
- SHAP 계산·입력값 표시·사진 검토를 작은 함수로 분리하고 코드를 Ruff 0.16.4의 스타일로 정리했다. 수식, 모델, 승인 제한, 서버 오류 내용은 바꾸지 않는다. 환경파일을 먼저 읽어야 하는 스크립트의 앱 import는 실행 함수 안으로 옮겼다.
- Ruff check/format 전체 통과. 로컬 전체 pytest는 모델링 의존성 matplotlib 미설치로 수집 단계에서 중단되어 전체 통과로 보고하지 않는다. 변경 관련 테스트와 GitHub Linux/MySQL 전체 검사 결과를 따로 확인한다.
- 브라우저 인증 이동 7개 흐름 및 로그인 진입/OCR 반영 7개 흐름·34개 상태를 다시 확인했다. 실기기 앱을 임의로 실행하거나 사용자 기록을 재계산하지 않았다.
- 변경 관련 Python 220개 통과(상태 코드 명칭 경고 1개). 자동 검사 3개의 최종 상태는 PR의 최신 커밋에서 확인한다.
